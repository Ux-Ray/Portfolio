Case Study

GamiDoc Evaluation Planning Flow

Designing a guided workflow to support evaluation planning for gamified systems.

GamiDoc is a web-based tool that supports researchers, educators, and practitioners in designing, documenting, and evaluating gamified systems through guided workflows. Before my work, GamiDoc had two main design phases: an earlier version focused on the gamification design framework and design documentation, and a later UX Archive version focused on UX methods, metrics, and evaluation resources.

Image placeholder: hero illustration and interface preview

Problem Statement

Users did not know where to start in GamiDoc.

I was asked to improve GamiDoc based on feedback reported in previous studies. While reviewing the earlier evaluations, I noticed that the problem was not only at a micro level, but at a broader structural level. Although GamiDoc offered useful resources for designing and evaluating gamified systems, users were not clearly guided through a coherent process. This could make it difficult for them to understand where to begin, how the different sections were connected, and how to move from general knowledge to concrete project decisions.

I wanted help choosing the right method.
When I followed links, I lost my progress.
It feels more like a textbook than a tool.
I didn't know where to start.

Main Insight

The issue was not only visual, but structural

The problem was not only visual, but structural. I redesigned GamiDoc's information architecture to move it from a feature/archive-centered system to a project-oriented workflow.

This change helped because it:

  • made the system easier to understand and navigate;
  • organized new features within a clearer structure;
  • turned evaluation planning into a dedicated workflow;
  • let users manage multiple projects and return to the right phase later.

Design Focus

From Structural Redesign to Evaluation Planning

After presenting the new information architecture, the ideas were well received by the team. However, because GamiDoc is a large system and my internship time was limited, I narrowed the scope to one concrete feature: Evaluation Planning. I translated it from research, using it to move project information into a live foundation.

Why this focus?

  • Addressed a key gap in the previous system.
  • Connected directly to the user's project workflow.
  • Turned UX knowledge into step-by-step guidance.
  • Was feasible to prototype and test during the internship.

Feature Design

Designing the Evaluation Planning Flow

After narrowing the scope, I designed Evaluation Planning as a step-by-step flow inside the user's project. The goal was to turn UX evaluation knowledge from the archive into a practical decision-making process. Instead of only reading about methods and questionnaires, users would be guided through key choices such as their evaluation goals, project stage, constraints, and suitable methods or instruments.

Image placeholder: evaluation planning flow diagram

The Evaluation Planning flow was designed to turn scattered UX knowledge into a guided decision-making process.

Prototype Design

From Flow to Interactive Prototype

After defining the flow, I translated it into wireframes and then into a high-fidelity prototype. The prototype was designed to feel guided but still flexible: users could follow the recommended path, browse all available methods, or manually select what best matched their project. It helped users define their evaluation setup, choose methods and instruments, and generate a final evaluation plan.

Design Decisions

Key Decisions Behind the Prototype

To make the Evaluation Planning flow useful in practice, I focused on four design decisions:

  • Step-by-step guidance: breaking the process into smaller decisions to reduce uncertainty.
  • Project-based choices: starting from the user's goals, project stage, and constraints.
  • Flexible navigation: allowing users to follow recommendations or browse methods manually.
  • UX Archive as support: using the archive as a knowledge source, not just a reading section.
  • Concrete final output: turning user choices into a generated evaluation plan.

User Testing

Validating the Evaluation Planning Prototype

To evaluate the prototype before implementation, I conducted a remote moderated user test with 14 participants. The study combined quantitative measures, including UMUX-LITE and rating-scale questions, with qualitative open-ended feedback. The goal was to understand whether users found the step-by-step flow clear, useful, and suitable for planning UX evaluations.

Quantitative result: the prototype achieved a UMUX-LITE score of 78.79, indicating an expected level of perceived usability. Participants also rated the main aspects of the tool positively, suggesting that the guided structure and recommendation process were generally well received.

Image placeholder: UMUX-LITE bar chart

Qualitative insights

  • Clear step-by-step structure: users appreciated being guided through the evaluation process instead of navigating resources independently.
  • Useful personalized recommendations: participants valued method suggestions tailored to their goals, project stage, and constraints.
  • Need for clearer explanations: some users wanted more guidance around certain terms, method selection, and why specific instruments were recommended.

Implementation

From Prototype to Front-End Development

After validating the prototype, the project moved into implementation. The Evaluation Planning flow is currently being developed in React and JavaScript as part of the GamiDoc web platform. I am contributing to the front-end implementation by translating the prototype into reusable components and interactive steps.

This case study is ongoing and will be updated after the feature is completed and evaluated through a second user study. The project is also being developed into a research paper documenting the design process, prototype evaluation, and implementation.
